# Как устроена интеграция с Aurral

Этот документ фиксирует контракт, который плагин использует, и решения, принятые при разработке.
Он опирается на исходники Aurral `v2.0.0` (`backend/services/plugins/`).

## Что такое плагин Aurral

Плагин — это папка `<data>/plugins/<id>` с двумя файлами:

- `manifest.json` — объявленные возможности и настройки;
- `index.js` — один ESM-бандл с `export default` объекта плагина.

Код выполняется в отдельном процессе Node.js. Плагину доступны встроенные модули Node и `fetch`, но
нельзя рассчитывать на `npm install`: все зависимости должны быть собраны в `index.js`. Именно
поэтому сборка использует Rollup, а не внешние пакеты во время выполнения.

Имя папки обязано совпадать с `id` из манифеста. После распаковки zip папка `yandex-music/` уже
содержит оба файла, поэтому требование выполняется автоматически.

## Контракт импорта плейлистов

Aurral вызывает `plugin.importList.fetch({ settings, libraryFolder, dataFolder, url })` и проверяет
ответ схемой:

- `name` — непустая строка до 200 символов;
- `artworkUrl` — необязательный `http(s)`-URL;
- `tracks` — до 5000 объектов `{ artist, title, album?, durationMs?, mbid? }`;
- `artist` и `title` — непустые строки до 500 символов, иначе трек отбрасывается
  (`normalizePlaylistTrack`).

Плагин возвращает `artworkUrl: null`, если обложки нет: схема допускает `null`.

Перед вызовом плагина Aurral сам проверяет:

- ссылка использует `https:`;
- хост совпадает с одним из `importList.hosts` или является его поддоменом.

Поэтому в манифесте перечислены только четыре домена Яндекс Музыки, а `src/url.ts` повторно
проверяет ссылку и отбрасывает чужие/похожие хосты, порты и лишние сегменты пути.

## Установка по ссылке на GitHub

Aurral запрашивает `releases/latest` у GitHub API. Если в релизе есть `.zip`-ассет, скачивается он.
Если релиза нет, используется zipball ветки по умолчанию — в таком архиве нет собранного
`index.js`, поэтому плагин не установится. Отсюда требование: перед установкой по ссылке на
репозиторий должен существовать релиз с ассетом.

Workflow `.github/workflows/release.yml` по тегу `v*`:

1. устанавливает зависимости;
2. запускает `npm run check` (типы, тесты с покрытием, сборка, упаковка, проверка архива);
3. сверяет тег с версией в `manifest.json`/`package.json`;
4. публикует `artifacts/aurral-yandex-music-plugin.zip` в GitHub Releases.

Архив содержит ровно один верхнеуровневый каталог `yandex-music/`, что соответствует ожиданиям
установщика Aurral (он снимает единственную обёртку).

## Почему только импорт

Plugin API 1 не предоставляет хуков обнаружения музыки, рекомендаций или метаданных, а также не
позволяет отдавать поток для скачивания. Встроенный Spotify в Aurral — это нативный провайдер
импорта с OAuth, а не плагин. Ближайший эквивалент для плагина — `importList`: пользователь
выбирает источник «Яндекс Музыка», вставляет ссылку, получает статический плейлист, а скачиванием
занимаются источники, настроенные в Aurral.

`downloadSource` сознательно не реализован: API Яндекс Музыки отдаёт зашифрованные стримы, а
расшифровка потребовала бы ключей и обхода защиты. Плагин остаётся в рамках метаданных.

## Аутентификация

API `api.music.yandex.net` требует OAuth-токен; анонимные запросы к плейлистам возвращают 403.
Плагин хранит токен в настройках Aurral (тип `password`), принимает как сам токен, так и вставленный
URL после редиректа, и никогда не логирует его.

## Ограничения контракта

- максимум 5000 треков за импорт — ограничение схемы Aurral;
- таймаут `importList.fetch` — 2 минуты, HTTP-клиент плагина — 30 секунд на запрос;
- «Мне нравится» — это плейлист kind `3`, отдельного API-хука для лайков в Plugin API нет;
- повторная синхронизация импортированного плейлиста заново вызывает `fetch` и заменяет треки.
